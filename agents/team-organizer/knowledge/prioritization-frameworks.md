# Prioritization frameworks

Reference for the prioritization frameworks worth reaching for, and when each fits.

## MoSCoW

Splits scope into four buckets: **M**ust have (non-negotiable for this release), **S**hould have
(important but not release-blocking), **C**ould have (nice to have if time allows), and **W**on't
have (explicitly out of scope for this round — stated so it isn't silently expected). Best for
scoping a single release or milestone where the deadline is fixed and the question is what fits.

## Eisenhower matrix

Splits work along two axes: urgent vs. not urgent, and important vs. not important. Work that's
urgent and important gets done now; important-but-not-urgent gets scheduled deliberately (this is
where most high-value work actually lives, and where it's easiest to let slip); urgent-but-not-
important gets delegated where possible; neither urgent nor important gets dropped. Best for
individual or team task triage, not release scoping.

## RICE scoring

Scores each candidate item on four factors — **R**each (how many users/customers it affects),
**I**mpact (how much it affects them), **C**onfidence (how sure we are about the Reach/Impact
estimates), and **E**ffort (how much work it takes) — combined as (Reach × Impact × Confidence) /
Effort to produce a comparable score across very different kinds of work. Best when comparing a
long list of unrelated initiatives competing for the same limited capacity.

## Choosing a framework

MoSCoW for "what fits in this release," Eisenhower for "what should I/we work on this week,"
RICE for "which of these ten different initiatives should we actually fund." Using the wrong one
for the situation (e.g. RICE-scoring a single sprint's tasks) adds process overhead without
adding clarity.
